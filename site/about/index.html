About

What this site is, who maintains it, and how to cite, reuse, and correct it.

What This Is

LLM Frontier tracks the cheapest way to reach each level of large language model capability, and how fast that cost is falling. It is a derived view of Artificial Analysis's measurements, rebuilt every three hours; the methodology page describes every derivation, and the data notes log what has happened to the record.

Who Maintains It

The site is a project of CatalystNeuro, a team that does data and software engineering for open neuroscience. The argument for why the cheap end of the range matters is in the post What Happens When the Cost of Intelligence Drops 100x. To work with CatalystNeuro, request a consultation.

Where the Measurements Come From

Every score, cost per task, and time per task is measured and published by Artificial Analysis; this site adds the history, the frontiers, the records, and the advances. Reuse of the measurements is governed by Artificial Analysis's terms. The code that builds the site, and the site itself, are in the llm-frontier repository under the BSD 3-Clause license.

How to Cite

Cite the site with the date you read it, since the numbers change every few hours, and credit Artificial Analysis as the source of the measurements:

CatalystNeuro. LLM Frontier. https://llm-frontier.catalystneuro.com/ (accessed YYYY-MM-DD). Measurements from Artificial Analysis, https://artificialanalysis.ai/.

@misc{llmfrontier,
  author       = {{CatalystNeuro}},
  title        = {LLM Frontier},
  year         = {2026},
  howpublished = {\url{https://llm-frontier.catalystneuro.com/}},
  note         = {Accessed YYYY-MM-DD. Measurements from Artificial Analysis.}
}

The repository carries the same information in a CITATION.cff file. For a figure that depends on one day's data, the commit history of the observation record gives a permanent reference for that day.

The Data

Everything the dashboard draws comes from one file, data/llm-frontier.json, rebuilt every three hours. Its main keys:

  • updated and updated_at: the date of the data, and the time it last changed.
  • models: one row per model, as an array: name, lab, release date, Intelligence Index, cost per task in US dollars, retired flag, open weights flag, the dated changes in cost and index, the capability scores in the order of capabilities, the index era the scores belong to, and the measured time per task, output speed, and time to first answer token.
  • capabilities: the metric behind each tab. eras: the dates on which the source recomposed the Intelligence Index.
  • tiers, tier_cost, and tier_summary: the cost records for each Intelligence Index tier, with the collapse and halving time derived from them. Keys beginning cap_ hold the same for each capability, and keys containing time hold the speed records.
  • advances: every date on which the frontier changed, newest first.
  • decision_models: the Decision Index contestants, in the same row shape, with costs per 1,000 tasks.

The file is shaped for the dashboard, and keys are added as the dashboard grows. The full observation history, with every dated cost and score per model, is data/history.json in the repository. The dashboard's Download CSV button gives the current models as a table.

Frontier advances are also published as Atom feeds: Overall, and one per metric (Coding, Agentic Tool Use, Long Context, Instruction Following, Factual Recall, Scientific Reasoning, Knowledge Work, Multimodal, Decisions).

Reporting a Problem

If a number looks wrong, open an issue on GitHub with a link to the view; the hash in the address bar records the tab, the highlighted model, and the slider dates. Corrections are logged in the data notes.
